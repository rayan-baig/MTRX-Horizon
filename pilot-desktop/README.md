# Pilot for Mac

Pilot is the MTRX Horizyn AI assistant as a Mac app: a small robot that floats above every app, on every desktop and over full-screen apps. Click it and a chat window opens next to it. It runs on the user's own AI key (Anthropic, OpenAI, Google Gemini, or any OpenAI-compatible API), so their provider bills them directly; there is no MTRX server in between.

People who just want the app: see [INSTALL.md](INSTALL.md).

## What it does

- **The robot**: the owner's robot artwork, 110 px wide at rest, with a soft glow and a status dot (green ready, amber no key yet, pulsing while thinking or looking). It moves around by itself (below). Drag it anywhere: where it's dropped becomes its home. Right-click it for Open Chat, Play a Trick, Speak Replies, Sounds, Calm / Relaxed / Always moving and Hide Pilot. No Dock icon; the menu bar shows the robot's head with Show/Hide Pilot, Open Chat, Settings, Play a Trick (Surprise Me, Classics, and the 80 tricks of 1.3 by category: Dances, Sports, Fun and Tricks, Moods, Screen, Seasonal), Energy (Calm, Relaxed, Always moving), Speak Replies, Sounds, Start at Login, About Pilot and Quit Pilot.
- **Chat window**: matches the design: glass panel with a blue-violet edge, the P-with-orbit mark, "Pilot", the greeting, five pill buttons, the message box, the gear, palette and ? buttons, and the "Bring Your Own API Key" card. Closing it leaves the robot. The first time, a short welcome shows three steps.
- **Keys**: several chat keys can be saved and switched, plus separate image and video keys. Models come from the provider's own model list for the key, or the user types one. Keys are encrypted with Electron `safeStorage` (the encryption key lives in the macOS Keychain); without the Keychain, Pilot refuses to save a key. Keys stay in the main process: windows only ever see the last four characters.
- **Seeing the screen**: only when the user asks: the eye button ("Look at my screen", "Explain this screen", "Summarise what I'm looking at", and "Help with what's on screen", which sends a fresh screenshot with each message while it's on), or after the user presses Allow on Pilot's "look at the screen" card. The first time, Pilot explains Screen Recording in plain words and opens the right pane in System Settings. A "Pilot is looking at your screen…" banner shows while a screenshot is taken and sent; Pilot's own windows are left out of the picture. Nothing is captured in the background.
- **Actions, all asked first**: look at the screen, copy a reply or draft to the clipboard, open an https website in the browser, save a note, remember a fact (only with memory on), make a picture or video (only with those keys). Several actions become a numbered plan: Approve all, Step through, or Cancel. There is no tool for payments, deleting files, sending messages or email, or typing into other apps.
- **Memory** is off by default; remembered facts and saved notes can be viewed and deleted in settings. **Voice**: macOS Dictation works in the message box.
- **Start at login** is on by default, with a switch in settings and the menu bar. Quit always quits.

## The moving robot (1.1, Always moving since 1.2)

The engine is the web core's (`pilot-motion.js` and `pilot-actor.js`, copied into `src/core/`; docs/PILOT.md describes the moves, poses and fallbacks). On the Mac:

- **One overlay window.** The robot lives in one transparent window covering the **work area** of the display its home is on (so never the menu bar or the Dock). It is always on top, on every Space and over full-screen apps, never focusable, and click-through: `setIgnoreMouseEvents(true, { forward: true })`, turned off only while the pointer is over the robot (the robot window checks forwarded mouse moves; the main process also checks the cursor a few times a second, so a file dragged from Finder can be dropped on the robot) or while it's being dragged (`src/main/overlay.js`, `MouseGate`). Moving the robot inside one big window is smooth and cheap (the compositor moves a small layer), where moving a small window 60 times a second from the main process would stutter. With several displays the overlay covers one: drag the robot onto another display and the overlay moves there with it (its home is remembered with the display).
- **Moves**: walk and run along the bottom, fly anywhere on the display (with a superhero landing), climb the left or right edge, tricks (backflip, spin, bounce, peek, celebrate, knee slide, power up), waves, glances at the mouse, and the sports tricks (football, soccer, tennis). Reactions: it celebrates when an action you allowed is done, sends hearts when you say thanks or come back after half an hour, points up once at start if there's no key yet, and does a playful "waiting" pose once when the chat has been open with nothing happening for a couple of minutes. The main process decides when (`src/main/life.js`, with `pilot-motion.js`'s rules); the robot window plans and plays the move.
- **Energy** (menu bar, right-click menu and settings): **Calm** (he only rests: breathing, blinking, a glance now and then), **Relaxed** (Pilot 1.1: a move every 30 to 120 seconds, resting most of the time) and **Always moving** (the default since 1.2). Settings from 1.0 and 1.1 move to Always moving, except Calm Mode turned on by the user, which becomes Calm (`migrate` in `src/main/store.js`). Under macOS's **reduce motion** the level is Calm unless the user picked one; a pick in the menu or settings always wins (`roam.level`).
- **Always moving** (`src/core/roam.js`, desktop only; the web robot keeps its toned-down rules): he's nearly always travelling. Walks and runs along the bottom edge, flights across to another spot (sometimes by way of a hover) ending in a superhero landing, climbs up either side edge and a drop or a flight back down. As soon as the robot window says a move has ended, `src/main/life.js` waits 1 to 4 seconds and sends the next one; now and then the pause is a quick look toward the mouse or a wave, and about every couple of minutes (80 to 160 seconds) a trick or sport: backflip, celebrate, knee slide, football, soccer, tennis or the energy ball. Destinations are random, in both directions, and never where the mouse is; if the pointer rests close to him during a pause, he moves on at once. Moves link standing up (no sitting down between them); with nothing coming next for 6 seconds he sits down to the resting robot. **Facing**: pictures are never mirrored (the P would be backwards). walk1 and run1 are drawn turned a little to the right and the knee slide to the left, so going right he walks or runs, and going left he skips sideways facing the camera, flies, or ends a dash in a knee slide; landings come straight down. Football and soccer are only picked when they'd go right, and tennis when its spot is to his right.
- **Holds** (Always moving): he keeps still while the chat is open (stopping right where he is, next to it), while something is full screen in front (window places from macOS, no permission needed, `src/main/frontmost.js`, asked at most every 15 seconds), while he's dragged or hidden, while the pointer is on him (so a click lands), and while the Mac is idle (`powerMonitor`, 2 minutes) or locked; then not even a blink. Holds are checked again every 2 seconds, and he waves when the user comes back (hearts after half an hour). Typing in another app doesn't stop him in Always moving.
- **Relaxed**: right before a move it checks once whether the user is typing (keys in use but the mouse still, from `powerMonitor`'s idle time and the cursor) and whether something is full screen, and keeps still then, while the chat is open, or while hidden or dragged. It waves when the user comes back after three minutes away (or unlocks the Mac), and gently when the chat opens.
- **Poses**: drop `<pose>.webp` or `.png` into `assets/poses/` with one of the pose names (docs/PILOT.md lists them and their fallbacks) and rebuild: no code change. `python3 tools/pilot_art.py` (in the repo root) scales the owner's pictures to the shared canvas.
- **Performance**: moves are Web Animations on transforms and opacity, on the compositor, with no script per frame. Pose pictures change only at a step (a class toggle, no new picture), cross-fades are capped at 160 ms (1.3), dust puffs come every other step and a flight leaves three glow puffs, and while travelling the pose pictures have one shadow and no glow (`.travel` in `robot.css`). At rest nothing animates except a blink (170 ms every few seconds) and one slow breath every 25 to 45 seconds, both from timers. The main process sleeps between moves (one timer), checks idle every 10 seconds and the cursor every 300 ms (a cheap call). Measured under xvfb on Linux with software rendering (a Mac with a GPU does better), the whole app (all its processes): about 3% of one core resting, about 8% walking back and forth with no pauses, about 6% in Always moving (see the 1.2.0 commit notes).

## Pilot for Mac 1.3: smoother, 80 tricks, the bigger pose sheet, paste, links, a voice and sounds

- **Smoother motion** (`src/core/roam.js`): springy easing made with CSS `linear()` (a damped spring sampled into the curve; a cubic overshoot where `linear()` isn't known), anticipation (a crouch that dips the other way first) before every take-off, squash and stretch on take-offs and landings, jumps on real ballistic arcs and flights on finely sampled curves (so the speed along them is right), banking and a gentle sway of the head and halo while travelling. The pose pictures are single images, so the head bob and halo wobble are a small rotation about his feet, which moves the head most. The walk alternates the real walk1 and walk2 frames (run1 and run2 for runs) with a bob timed to each step and a small forward lean; the step time is the stride divided by the speed, so his steps keep time with how fast he goes and his feet don't slide. Pictures cross-fade at the footfall (at most 160 ms). All transforms and opacity, on the compositor.
- **Frame pacing**: every pose picture (and the prop pictures) is fetched and decoded (`img.decode()`) when the robot window starts, before its first use. Measured under xvfb while roaming with tricks: 99% of frames within 16.8 ms, none over 50 ms in the runs reported in the 1.3.0 commit notes.
- **The owner's bigger pose sheet**: 52 poses and 6 props, prepared with `tools/poses.py` (each picture scaled so its head matches the standing robot's, measured by its visor, centred on the face, on one baseline, WebP). Poses whose props reach further sit on a bigger canvas (600 × 400), sized in `tricks.css` and marked by `robot.js` once decoded. The new pose names (catch, baseball, bowling, browse, cartwheel, confetti, draw-smiley, fireworks, hang, heart-eyes, juggle, kite, knock, laptop, laugh, lounge, magic, meditate, paint, paper-plane, peek-door, peek-window, point-screen, pumpkin, shiver, shy, trampoline, ski, sled, sneeze, snowball, snowboard, snowman, sparklers, spin, surf, teleport, umbrella, yawn) are the Mac's own (`EXTRA` in roam.js, each with a fallback); the sheet's walk1, walk2, run1, run2, standing, wave, fly, flip, sitting, throw, kick, tennis and love replace the old ones; climb1, land, celebrate, slide, point, power and arms-crossed (not in the new sheet) are kept. Pictures are never mirrored.
- **80 tricks** (`src/core/tricks.js`), each a named, choreographed move in a category, built from the poses, transforms, small props and effects drawn in SVG (`src/renderer/props.js`, attributes only, so the CSP is fine) and the owner's prop pictures. Each walks (or lands) somewhere with room for it first, uses only pictures that face the way he goes, fades every prop out before it ends (the actor removes them), and ends standing on the floor. They're in the menus by category; "Always moving" picks one every minute or two (travel stays the main thing; about one in five is a classic). Seasonal ones only in their season by the Mac's date (northern-hemisphere seasons; pumpkin in October, Holiday Hat in December, fireworks and the countdown from 30 December to 2 January, snow in winter, umbrella in spring and autumn), Good Morning only from 5 to 11 am and Good Night only from 8 pm to 5 am. Picked from the menu, any of them plays any day (the menu says when one is in season).
- **Sounds** (`src/renderer/sounds.js`): applause, short tunes for dances, a whoosh, a bat's crack, a kick, a boing, chimes, sleigh bells, a spooky-cute wobble, fireworks, a camera shutter, a knock, a cute yawn and sneeze (not a voice), all made with the Web Audio API in code: no audio files. On at a low volume; never while muted (asked of macOS with `osascript`, arguments only, at most every 15 s), full screen, away or locked, during quiet hours (9 pm to 7 am unless changed) or while Pilot speaks; one at a time and 20 seconds apart unless the trick was picked from the menu.
- **Speak replies** (`src/renderer/speech.js`, off unless turned on): the speaker button by the gear, in Settings and in the menus. The Mac's own voices through the Web Speech API (the most natural English voice installed, Premium or Enhanced first, never a novelty voice; a normal speed and a slightly brighter pitch), sentence by sentence while a reply streams; `say` from the main process (arguments only, no shell, capped) if Web Speech has no voices. Code, long links, emoji and markdown aren't read aloud. A click on the speaker or the robot stops him; so do closing the chat and sending a new message. Silent while muted, locked, idle or full screen. While he speaks the resting robot's eyes glow softly and his head bobs a little.
- **Paste and links** (`src/main/clip.js`, `src/renderer/links.js`): Cmd+V attaches a screenshot or a copied picture straight from memory (nothing written to disk), or a picture or video copied in Finder, through the same shrink-to-fit path as a dropped file; text and links paste as text. Web addresses in messages (both ways) become links, only https, http and mailto; a click asks "Open this link?" with the address, then opens the default browser. Right-click: Copy Text, Copy Link, Copy Image (as a picture), Save Image, and Cut, Copy, Paste and Select All in the message box.
- **Read this link** (`src/main/linkread.js`): a chip under the message box for each web link (on by default for a single pasted link). On send the main process fetches it with `net.fetch`: http and https only, no cookies, 10 seconds and 2 MB at most, redirects followed by hand; never a local, private-network or file address (every address of the host is checked, and again on each redirect). A page goes along as its title and main text (scripts and styles stripped, about 20,000 characters at most); a picture is attached instead. "Reading link…" shows while it works; a page that can't be read gets a plain line.

## Screen access and dropped files (1.1)

- **Screen access** in settings: the live macOS permission (Allowed or Not allowed), Open Mac settings, Check again, and Relaunch Pilot when macOS needs a restart to apply it. Modes: **Off** (the eye is hidden and the screen action isn't offered), **Only when I ask** (default) and **Help with what's on screen** (a fresh screenshot with each message). Nothing between messages; the "Pilot is looking" banner every time. The first-run welcome offers to turn it on and notices when it's allowed.
- **Pictures and videos**, dropped on the chat or the robot, pasted, or picked with the paperclip, any size (`src/renderer/attach.js`). Pictures (PNG, JPEG, HEIC, WebP, GIF) are shrunk on a canvas until each fits the provider's limits (a per-provider table, no model names); HEIC is opened by macOS first. Videos use Google Gemini's resumable file upload (`src/main/uploads.js`, 8 MB pieces with a progress bar) with a Gemini key; with other providers Pilot takes up to 24 evenly spaced frames and says so ("I looked at 24 frames from your 3-minute video."). A video is read from disk a piece at a time, never whole. Each waits under the message box with a thumbnail, name, size and a remove button. A model that can't take pictures gets a plain message and a "Switch key or model" button.

## Typing in the chat (fixed in 1.1)

In 1.0 the chat was a non-activating panel in a menu-bar app, so it never became the key window and typing went to the app in front. Now the chat is an ordinary frameless window (still on top, on every Space and over full-screen apps); opening it brings Pilot forward (`app.focus({ steal: true })`, it's always the user's click), focuses the window and the message box; a click in it makes it key again; and closing it hands the keyboard back to the app that was in front. The app menu has the standard Edit items, so paste, copy, select all and undo work. The smoke test checks the focused window, the focused message box, the Edit menu, real keystrokes where the Mac allows them, and a full conversation against a pretend provider on the same computer.

## How it's built

```
src/main/       main process: windows, menu bar, IPC, key store, screen capture, CSP,
                the robot's overlay and timing, screen access, uploads
src/preload/    the small API the windows get (contextBridge)
src/renderer/   robot.html and chat.html (no inline scripts or styles), attach.js
src/core/       chat engine, providers, media, safe renderer, desktop tools, the moving robot, roam.js (Always moving), tricks.js (the 80 tricks)
assets/         the robot artwork (and its three resting layers), poses/, props/, its menu-bar head, the app icon
tools/          poses.py: prepares the owner's pose sheet (a developer tool, not in the app)
build/          icon.icns, the .dmg background, entitlements (for signing later)
test/unit/      node:test unit tests
test/smoke/     Playwright-for-Electron smoke test (also takes the screenshots)
```

### Shared core

`src/core/pilot-providers.js`, `pilot-media.js`, `pilot-render.js`, `pilot-motion.js`, `pilot-actor.js` and `pilot-actor.css` are copied unchanged from the web Pilot core **1.1.1** in `static/pilot/`; `src/core/core-version.json` records their checksums and a test checks them. The desktop layers `providers.js` and `media.js` build on the core's adapters, adding pictures (screenshots in messages and tool results) and running in Node. `engine.js` is the desktop's own engine with the same structure and host interface as the core's `pilot-engine.js`; it is separate because the Mac needs pictures in tool results, every action asked first, and older screenshots dropped from what is sent again.

To update the core: copy those files from `static/pilot/` over, update `core-version.json`, and run `npm test`.

### Security

- Every window: `contextIsolation: true`, `nodeIntegration: false`, `sandbox: true`, a preload with a fixed list of calls, no navigation, no new windows, no webviews, all permission requests refused.
- Windows load only Pilot's own files from a `pilot://` scheme, each served with a strict Content-Security-Policy: no inline scripts or styles, no eval, `connect-src` limited to the three providers' API hosts plus the user's own compatible address. Any other request from a window is cancelled.
- AI calls run in the main process, only to those same addresses, without cookies.
- "Open a website" uses `shell.openExternal` with https only, after the user presses Allow.
- Electron fuses turn off `RunAsNode`, `NODE_OPTIONS` and the inspector flags, and only load the app from its checked asar.

## Develop

```
npm ci
npm start          # run Pilot

```

## Releases

`.github/workflows/pilot-desktop.yml` runs on `macos-latest` for every push that changes `pilot-desktop/**`, and by hand. It runs the tests and the smoke test, builds a universal (Apple Silicon + Intel) `.dmg`, checks it, uploads it as a workflow artifact, and creates or updates the GitHub Release **Pilot for Mac vX.Y.Z** (tag `pilot-mac-vX.Y.Z`, from `version` in `package.json`) with the `.dmg` attached. The release text comes from `RELEASE_NOTES.md`.

### Signing (needs the owner)

The app is ad-hoc signed for now, so people press "Open Anyway" once (INSTALL.md). Signing and notarisation turn on by themselves when these repository secrets exist: `CSC_LINK` and `CSC_KEY_PASSWORD` (a Developer ID Application certificate as base64 .p12 and its password), and `APPLE_ID`, `APPLE_APP_SPECIFIC_PASSWORD` and `APPLE_TEAM_ID`. That needs a paid Apple Developer account, held by an adult.
